Bun is required. The package pins its native intelligence dependencies and dprint where binary compatibility matters.

## From a package registry

Install ast-mcp into a repository so its native intelligence and dprint dependencies remain available, then connect every supported host:

```npm
npm install --save-dev @mwillbanks/ast-mcp
```

When installing with Bun, allow the package's pinned native installers:

```bash
bun pm trust dprint
```

Run the repository-local executable so the configured MCP and hooks retain a stable package path:

```bash
./node_modules/.bin/ast-mcp install \
  --scope local \
  --target all
```

This installs stdio definitions by default. To install Streamable HTTP definitions, add `--transport http --host 127.0.0.1 --port 3768`. Add `--service` for a macOS LaunchAgent or Linux systemd user service; otherwise start the manual HTTP command printed by the installer. Windows supports manual HTTP startup only.

Bun blocks transitive lifecycle scripts by default, so the explicit trust step runs the pinned dprint installer before the MCP starts. If another package manager blocks dependency build scripts, approve `dprint` through that manager. npm, pnpm, Yarn Classic, and Yarn 2+ project layouts are supported. Binary lookup checks ancestor package bins, package metadata, package-manager global bins, and `PATH`.

Targets are `codex`, `claude`, `copilot`, or `all`. Local surfaces always use `./node_modules/.bin/ast-mcp`; global surfaces use a recognized Bun, npm, pnpm, or Yarn global-bin alias. Generated definitions omit MCP environment fields. Local installation creates project configuration. Global installation creates project-neutral user configuration.

## Platform support

The native Bun implementation supports macOS, Linux, and Windows without a Rust or Cargo prerequisite.

Optional native parser or embedding artifacts report explicit capability errors when a platform package is unavailable.

## From a source checkout

```bash
bun install
bun run build
bun run bin/ast-mcp.ts install \
  --scope local \
  --target all
```

Restart or reconnect the host's MCP servers after installation. A configuration file cannot activate a server in an already-running host process.

## Verify the installation

Confirm that these file-boundary tools are callable:

- `file_hash`
- `file_read`
- `file_write`
- `file_patch`
- `file_chattr`
- `file_delete`

Then confirm direct intelligence tools such as `digest`, `show`, `context`, `impact`, and `run`.

The installed skill includes a checker:

```bash
bun run scripts/check-install.ts \
  --scope local \
  --target codex
```

## Update or remove

Use `update` to reconcile managed surfaces and migrate version 1 configuration. Use `uninstall` to remove managed host surfaces while preserving configuration. `--root` remains deprecated for one release.

```bash
./node_modules/.bin/ast-mcp update \
  --scope local --target all

./node_modules/.bin/ast-mcp uninstall \
  --scope local --target all
```
