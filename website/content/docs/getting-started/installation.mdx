AST-MCP ships compiled executables with embedded Bun for six targets. The regular bundle uses a separate Bun installation as a fallback. Runtime formatting is disabled by default and uses only formatters you install and configure.

## From a package registry

Install ast-mcp into a repository so its native intelligence dependencies remain available, then connect every supported host:

```npm
npm install --save-dev @mwillbanks/ast-mcp
```

For a persistent global install, run `npm install -g @mwillbanks/ast-mcp`.

Available since NEXT_RELEASE, npm selects the matching compiled executable automatically. Installation works with `--ignore-scripts`. The installed `ast-mcp` command uses Node to locate and start the executable. The executable embeds Bun and runs without npm. Use `ast-mcp-bun` to run the fallback bundle directly with Bun on `PATH`. Compiled installations download the executable and its native runtime assets in addition to the regular package.

To enable formatting, install a formatter separately and follow the [optional formatting guide](/docs/guides/formatting).

Run the repository-local executable to install host entries for the project package:

```bash
./node_modules/.bin/ast-mcp install \
  --scope local \
  --target all
```

This installs stdio definitions by default. To install Streamable HTTP definitions, add `--transport http --host 127.0.0.1 --port 3768`. Add `--service` for a macOS LaunchAgent or Linux systemd user service; otherwise start the manual HTTP command printed by the installer. Windows supports manual HTTP startup only.

npm, pnpm, Yarn Classic, and Yarn 2+ project layouts are supported. Binary lookup checks ancestor package bins, package metadata, package-manager global bins, and `PATH`. ast-mcp never downloads formatter binaries during file operations.

Targets are `codex`, `claude`, `copilot`, or `all`. Stdio definitions pass `mcp`. A local definition sets the project directory as `cwd`. The installer selects the launch path for the compiled executable or the Bun package. Generated definitions omit MCP environment fields. Local installation creates project configuration. Global installation creates project-neutral user configuration. Clients that support MCP Skills can discover the canonical skill from the server. Unsupported clients can use `ast-mcp skills export <destination>`; see the [skills guide](/docs/guides/skills).

## Platform support

Compiled npm targets are macOS arm64, Windows x64, and Linux arm64 and x64 with glibc or musl. Alpine arm64 requires `gcompat` for the bundled Markdown parser. Other targets can use the Bun bundle where Bun and the native dependencies are supported.

Optional native parser or embedding artifacts report explicit capability errors when a platform package is unavailable.

For a standalone install outside npm, download the matching [GitHub release archive](https://github.com/mwillbanks/ast-mcp/releases/latest) and keep `runtime/` next to the executable.

## From a source checkout

```bash
bun install
bun run build
bun run bin/ast-mcp.ts install \
  --scope local \
  --target all
```

Restart or reconnect the host's MCP servers after installation. A configuration file cannot activate a server in an already-running host process. If startup fails or tools disappear, follow the [connection diagnosis guide](/docs/guides/connection-diagnosis).

## Verify the installation

Confirm that these file-boundary tools are callable:

- `file_hash`
- `file_read`
- `file_write`
- `file_patch`
- `file_chattr`
- `file_delete`

Then confirm direct intelligence tools such as `digest`, `show`, `context`, `impact`, and `run`. If the host supports MCP Skills, verify that it can discover and load the `ast-mcp` skill. Otherwise, export the skill explicitly and configure the host to load that directory.

An exported `ast-mcp` skill includes an installation checker. From the exported skill root, run:

```bash
bun run scripts/check-install.ts \
  --scope local \
  --target codex
```

## Update or remove

Use `update` to reconcile managed surfaces and migrate version 1 configuration. Use `uninstall` to remove managed host surfaces while preserving configuration. `--root` remains deprecated for one release.

```bash
./node_modules/.bin/ast-mcp update \
  --scope local --target all

./node_modules/.bin/ast-mcp uninstall \
  --scope local --target all
```
